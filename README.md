# ⚡ AI-Powered Agile Sprint Manager

---

## 🎯 Project Overview

An AI-powered Jira-like Agile Sprint Management System that automates:

- Sprint planning, backlog, and task prioritization
- ML-based task completion time prediction (Random Forest)
- Automatic blocker and delay detection, plus rule-based insights
- Risk scoring, velocity forecasting, and sprint health grading
- Performance analytics and sprint reports

## 🚀 Setup & Run

### Step 1: Install dependencies

```bash
pip install -r requirements.txt
```

### Step 2: Configure authentication (Supabase)

The app gates access behind Supabase email/password auth. Set:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

Either in a `.env` file in the project root (loaded by `auth.py`) or in Streamlit Cloud **Secrets** with the same keys. Without valid credentials, login and signup will not work.

For local development you may need to adjust Supabase Auth (for example email confirmation) so users can sign in.

### Step 3: Run the app

```bash
streamlit run app.py
```

On first run, the SQLite database is **created and seeded** via `data/db_setup.py` (tables + sample project). No manual SQL setup is required.

### Hardware requirements (reference)

- Processor: Intel i5 or equivalent
- RAM: 8 GB minimum recommended
- Storage: sufficient space for Python, dependencies, and the SQLite file

## 📱 App Tabs (UI)

| Tab | Purpose |
|-----|---------|
| **Summary** | KPIs, status charts, rule-based insights, blocker warnings, AI sprint intelligence, recommendations, activity feed, velocity and work-type breakdown |
| **List** | Filterable task list with AI risk labels (auto-flagged / delayed / at risk) and inline edit |
| **Board** | Kanban columns: Todo, In Progress, Done, Blocked, with AI badges |
| **Sprints** | Create/edit sprints, start/complete/delete (manager), backlog → sprint moves |
| **Task Creation** | Create tasks with ML time prediction and risk hint; browse/edit backlog tasks |
| **Team** | Members, roles, velocity, per-sprint workload |
| **AI Insights** | Auto detection, time predictor, velocity forecast, risk table, recommendations + rule insights |
| **Reports** | Per-sprint report: health, risk, status distribution, task table |

**Roles:** After login, users have a **Manager** or **Member** role (stored in Supabase user metadata). Managers can create projects, sprints, and tasks; members see a filtered task view aligned to their profile where applicable.

## 🤖 AI / Analytics Modules

### `models/ml_engine.py`

1. **CompletionTimePredictor** — Random Forest on historical tasks with logged `actual_hours` in **completed** sprints; heuristic fallback if fewer than five training rows.
2. **AutoBlockerDetector** — Stagnation, hour overruns, deadline pressure, priority vs. sprint progress, capacity and velocity heuristics.
3. **RiskDetector** — Per-task and per-sprint rule-based risk scores.
4. **VelocityForecaster** — Weighted moving average, trend, confidence.
5. **RecommendationEngine** — Actionable cards from sprint risk, blockers, velocity trend, workload balance.
6. **compute_sprint_health** — Score / grade from completion, blockers, points, critical work.

### `ai_module.py` & `blocker_detection.py`

- **ai_module.py** — Light rule-based insights (pending count, uneven assignee load, high-priority backlog pressure).
- **blocker_detection.py** — Overdue `due_date` and “stuck in progress” staleness warnings.

These are **imported by `app.py`**, not duplicated inside it.

## 📊 Database (SQLite)

Main tables:

```text
projects        — project metadata
team_members    — people, roles, velocity, avatar color
sprints           — sprint window, status, planned/completed points
tasks             — work items, assignee, hours, tags, blocker notes
sprint_metrics    — velocity and completion stats per completed sprint
activity_log      — audit-style events (create/update, etc.)
```
